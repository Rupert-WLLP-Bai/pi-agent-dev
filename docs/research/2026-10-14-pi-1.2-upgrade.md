# Pi 1.2.0 升级记录

核对日期：2026-10-14。将嵌入式审计 Agent 从 Pi 0.85.1 升级到官方当前稳定版 **1.2.0**，发布日期为 2026-10-12。

## 版本与来源

- `@earendil-works/pi-coding-agent`、`@earendil-works/pi-ai` 均精确锁定为 `1.2.0`，`bun.lock` 同步更新。
- 审计工具使用 `typebox@1.3.27`，与 SDK 的 schema 类型一致；API 自身的 Elysia schema 仍由其依赖管理。
- `PI_AGENT_VERSION` 为 `1.2.0`，新 Agent Run 持久化此版本；历史运行保留原版本。
- SDK 声明的 Node engine 为 `>=22.19.0`；本仓库仍使用 Bun，CI 和容器固定 Bun 1.4.0。

官方依据：[npm 元数据](https://registry.npmjs.org/@earendil-works%2Fpi-coding-agent/1.2.0)、[v1.2.0 发布说明](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/CHANGELOG.md)、[官方更新记录](https://pi.dev/changelog.xml)、[SDK 文档](https://pi.dev/docs/latest/sdk)。版本固定的发布说明用于追溯，`latest` 文档可能继续变化。

## 本次采用的改进

### 隔离审计会话资源

`packages/pi-agent/src/runtime.ts` 显式构造 `DefaultResourceLoader` 和内存 `SettingsManager`，将 `payment-terms-audit.skill.md` 的正文设为系统提示。关闭扩展、技能、提示模板、主题、项目上下文文件发现，并清空追加系统提示。资源加载器、会话与内存会话历史使用相同的模块工作目录。

模型声明的 `thinkingLevel` 为 `off`；保留既有 OpenAI-compatible 网关配置，包括 `enable_thinking: false` 和禁用 developer role。内存凭据、模型配置与会话历史沿用现有架构，审计快照与运行记录仍由应用持久化。

模型可调用的工具为以下六项：

- `get_rule_assessments`
- `get_evidence`
- `get_contract_document`
- `search_contract`
- `read_contract_block`
- `submit_finding_proposal`

运行协议回归测试从含有 `AGENTS.md` 和 `.pi/APPEND_SYSTEM.md` 哨兵文本的临时工作目录启动真正的 SDK，并接入本地流式网关。检查实际 HTTP 请求中的指令隔离、工具集合、角色与 thinking 设置，以及工具返回的规则评估。

### 对齐工具 schema

`packages/pi-agent/src/tools.ts` 改为从 `typebox` 导入 `Type`，工具测试从 `typebox/value` 导入 `Value`。旧的 `@sinclair/typebox` 0.34 与新版 TypeBox 1.x 使用不同的 schema 类型标记；统一依赖避免参数静态推导和运行校验跨版本混用。

### 使用原生工具计时

Pi 1.1.0 起，`tool_execution_end.durationMs` 记录 `execute()` 的单调时钟耗时。`packages/pi-agent/src/trace.ts` 使用该字段并取整，满足现有持久化毫秒字段的整数约束。缺失、非有限或负值记为 `null`。

删除以 `Date.now()` 计算工具起止差值的 Map。回归用例令墙上时钟跳过 2500 ms，同时 SDK 报告 25.6 ms；轨迹应保存 26 ms。工具轨迹时间戳仍是墙上时钟，前端推导的模型生成区间仍使用事件时间戳。

## 兼容性结论

`ModelRuntime.create`、`registerProvider`、内存凭据与模型 store、`createAgentSession`、`defineTool`、`SessionManager` 和会话事件订阅仍适用于当前集成。1.2.0 移除了实验性的 client/plugin 子路径，本仓库使用根导出，不受影响。

新版对未知 OpenAI-compatible 地址默认关闭 strict tool schemas，减少网关不支持严格 JSON schema 时的协议风险；工具参数、Finding Proposal 与确定性规则结论仍由现有代码校验。

取消仍通过 `AbortSignal` 和 `session.abort()` 传播；结束时仍解除订阅、释放会话，并由现有运行结果控制轨迹完成或失败状态。

## 其他可用功能

| 版本 | 功能 | 对当前系统的意义 |
| --- | --- | --- |
| 1.0.2 | `samplingParamsByThinkingLevel` | 可按模型 thinking level 配置采样；当前网关配置没有这一需求。 |
| 1.0.4 | 工具名称 glob 与排除列表 | 支持动态工具集合；审计使用明确的六工具集合。 |
| 1.1.0 | `agent_settled.aborted`、助手消息 `durationMs` | 可供后续取消状态和模型耗时展示设计使用；本次采用工具原生计时。 |
| 0.99–1.2 | `outputSchema`、`structuredContent`、namespace aliases、`reachesTools` | 用于结构化输出和工具编排；当前审计端口与工具边界不需要这些接口。 |
| 1.2.0 | 发布 settings/models/keybindings/themes JSON schemas | 主要改善 Pi 配置编辑体验，当前服务通过程序化配置创建会话。 |

Fullscreen TUI、剪贴板 OSC、OpenRouter 按 key 获取模型列表等功能针对 Pi CLI。MCP、codemode 和 tool_search 需要显式创建对应扩展，当前审计会话未加载。
