## 2. 测量方法（每个指标怎么做）

### K1 提交到首次风险

- 口径细节：以**规则评估**时间为准（不等 Agent）；若案件无任何冲突，记 `null`（不记 0）。
- 实现：从 `audit_snapshots` 的评估数组或轨迹首个 `POLICY_CONFLICT` 相关步骤取时间戳；建议由 QA 加一个只读统计脚本，不污染业务表。
- 报告：p50/p95 + 样本量 + 是否 fake 模式（fake 与真实模型分开报）。

### K2 人工复核工时

- 口径细节：活跃时长 = 复核页面 focus 且有待提交操作的时间；简单做法是用操作日志两条时间戳差（打开→提交），标注为"会话内时长"近似。
- 诚实声明：无埋点则不产出数字；不用"预计节省 X%"代替测量。

### K3 可复现部署时间

- 方法：第三方按 `PROJECT-BRIEF.md` §7 命令执行并记录起止；区分"有 Docker 经验/无经验"。
- 通过判据：`/api/health` ok + `bun run verify` 全绿 + 演示栈可开。

### K4 规则回归通过率

- 方法：`POST /api/rules/:id/validate` 的 Validation Run；按规则与版本分别报告，不合并成单一百分比。
- 边界：恰达阈值案例单独计数（通过/失败都说明口径）。

### K5 影子冲突率

- 前提：S2 持久化完成。只统计**同命题**互斥（类型不同/范围不同/仅概率不同不算冲突，契约 §5）。
- 分母定义：成功且可比较的影子建议数（排除 FAILED/SKIPPED）。

### K6 缺陷修复周期

- 方法：从 Git 与 issue 重建；按严重级（P0–P3）分组；只统计已关闭项。
- 局限：无 issue 追踪的修复只能按提交间隔近似，标注近似口径。

### K7–K12 已测量项

- 引用时必须带 commit/配置/样本量；不同 commit 的数字不可平均。
- 单样本指标（K9–K11）在对外材料中写作"单样本实测"，并附样本描述。

## 3. 未测量即未测量（对外口径）

| 常被问到的数字 | 我们的状态 |
| --- | --- |
| 准确率/召回率提升 | 未测量（无基准数据集与专家签核标签） |
| 人力成本节省比例 | 未测量（无工时埋点与对照） |
| 审查吞吐提升 | 未测量 |
| 影子模型准确率 | 未测量（冒烟仅验证可推理与延迟） |
| 生产可用性/恢复时间 | 未测量（无生产部署） |

这些进入"测量计划"而非"成果"；等 Main 提供最终测试/模型/浏览器指标后，由 Docs 按同一口径回填。
