# 任务管理

## 两层结构

[Master Roadmap / TASK-BOARD](./TASK-BOARD.md) 是全项目唯一任务入口，保存原任务 ID、当前任务、依赖、历史状态与证据。子工作包通过该板链接并保存明细；旧矩阵是历史快照。OMP TODO 是当前 Milestone 的执行视图，允许只显示关键任务和当前工作包入口，不承担全项目存档。

## 切换或新增工作包

1. 先读取任务板、当前交接和相关子工作包，核对其现有 ID、状态及依赖。
2. 新任务先追加到持久任务记录，关联总体 M1/M2/M3/M4。与旧任务重叠时保留两者 ID，标注父子或关联关系。
3. 重建 OMP 视图前，把被移出视图的任务名称、状态及映射保存到仓库；快照仅作历史证据，不作为另一份当前任务板。
4. OMP 视图使用持久 ID 加原任务名称，只列当前 Milestone 的关键执行项及工作包入口；下次从该视图读取当前进度。保留全局完成状态、阻塞原因及下一项。不能因面板看不见而删除或重置任务。

## 状态与验收

当前任务状态使用 `TODO / IN_PROGRESS / BLOCKED / DONE / CANCELLED`。历史的“已实现待统一验收”映射 `IN_PROGRESS`，同时保留其原文；历史能力分类与计划延期说明不冒充任务完成状态。`CANCELLED` 必须附用户明确取消的来源；取消某一子范围不取消整个父任务。

每条任务保存：ID、名称、模块、所属总体 Milestone、状态、优先级、依赖、负责人、证据或 Commit、最近更新。原记录未提供的字段写“未记录”，不凭编号或习惯补造。新补充的映射与依赖标明为本次整理决定，与原始要求分开。

完成实现与完成验收分开记录。代码存在、提交成功、局部 smoke 通过都不能自动关闭全范围任务。`DONE` 需要与该任务验收条件对应的来源；未执行的检查写待执行，外部前置条件写 `BLOCKED` 及解除条件。阶段、父任务和子任务各按自身验收条件判断，不用一项成功批量标绿。

## 每次交接

同步持久任务状态、[HANDOFF](./HANDOFF.md) 和 OMP 当前视图；注明候选 SHA、执行命令、退出码、证据位置与限制。保留计划时间、Git 提交时间和实际验收时间的区别。开发周期固定为 2026-09-11 至 2026-11-10，V1 截止 2026-11-10；TI 等子工作包沿用该周期。
