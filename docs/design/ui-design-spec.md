# 合同智能审计智能体 — UI/UX 设计规格 v1.2

> 版本：v1.2 · 2026-09-11  
> 比赛：第一届黄桷树AI智能体开发大赛  
> 课题：合同智能审计智能体——基于多源核验与证据驱动的合同风险审查  
> 范围：信息架构、核心页面与扩展页面设计；本轮不实现业务功能

## 0. 评审结论

v1.1 的方向基本正确，但有四个结构性问题：

1. **详情页仍以卡片为中心，而不是以合同原文为中心。** 合同审查的核心动作是定位原文、核对依据、作出判断。新方案改为同步联动的三栏审查工作区。
2. **领域词和数据身份混淆。** `Audit Case` 必须统一显示为“审计案件”；审计 ID 不是合同编号，合同名称也不能从 UUID 推断。
3. **驾驶舱指标会误导。** “风险命中”和“人工复核率下降”都不天然代表质量提升。新方案分开运营指标、质量指标和风险结果，风险分布用可比较的横向条形图，不用环形图。
4. **品牌区和导航过重。** 中国移动素材为白底横图，不能在深色侧栏上直接反白；新方案使用白色品牌承载板并压缩品牌区高度。规划导航可以完整，但正式构建只展示已有页面，不使用大面积“即将上线”占位。

设计目标：**让复核人先看到有问题的原文，再看到可追溯依据，最后完成明确的人工结论。**

## 1. 产品语言与设计原则

### 1.1 领域语言

UI 必须遵守根目录 `CONTEXT.md`：

| 领域对象 | 中文 UI 名称 | 禁止替代词 |
|---|---|---|
| Contract | 合同 | 文档对象 |
| Contract Revision | 合同版本 | 最新合同 |
| Contract Document | 合同原文 | 解析结果 |
| Audit Case | 审计案件 | 任务、Agent 会话 |
| Agent Run | 智能体运行 | 审计案件 |
| Finding Proposal | 风险发现 / 待复核发现 | 最终结论 |
| Human Review | 人工复核 | 自动审批 |
| Rule Assessment | 规则评估 | 模型意见 |
| Evidence Locator | 证据定位 | 单纯引文 |

界面标题、搜索占位、空态、按钮、表格列和通知文案都使用同一套词汇。现有“审计任务”全部切换为“审计案件”。

### 1.2 五条设计原则

1. **原文优先**：风险详情不能脱离合同上下文。
2. **证据可追溯**：每个发现都能跳到稳定的 `EvidenceLocator`，显示来源、区块和字符范围。
3. **规则与模型分离**：确定性规则评估不被智能体解释覆盖。
4. **颜色是辅助手段**：风险同时用文字、图标/形状和排序表达，不只靠红绿。
5. **展示真实能力**：未实现的路由不出现在比赛演示主导航；产品蓝图另行保留。

## 2. 品牌与设计系统

### 2.1 品牌锁定区

素材（统一放在 `apps/web/public/brands/`，Vite 直接按 `/brands/*` 提供）：

- `chinamobileltd-com-logo.png`：中国移动图形标识，**仅图标、无文字**，256 × 256 方形，浅灰底（约 60% 内容）。（原 `chinamobile.png` 实为 WebP 编码，已废弃。）
- `hjs.png`：黄桷树赛事标识，透明背景，已优化为 48 × 48。

因为中国移动素材只有图标没有文字，侧栏用「方形图标承载板 + 显式中文名」组成锁定区，而不是靠横版字标：

```text
┌──────────────────────────┐
│ [图标] 中国移动            │  30 × 30 白色承载板 + 14px/650 文字
│ 合同智能审计智能体         │  14px / 600
│ [黄桷树] 第一届黄桷树…      │  24px 标识，单行省略
```

承载板带 `--missing` 回退（显示「移」字），即使素材缺失品牌区也不会留空白。不使用 CSS `filter` 反色，也不把图标拉伸成横版比例。

完整课题名只出现在登录页、关于页、打印页和 `title`/可访问名称中，不塞入常驻侧栏。

## 3. 信息架构

### 3.1 产品蓝图

12 个侧栏目的地，14 个路由页面；详情/编辑页不占侧栏入口。

```text
总览
└─ 审计驾驶舱                 /dashboard

审计作业
├─ 审计队列                   /audit-cases
├─ 复核中心                   /reviews
└─ 整改跟踪                   /remediations

规则治理
├─ 规则管理                   /rules
├─ 案例验证                   /cases
└─ 法规知识库                 /regulations

能力与集成
├─ 能力插件                   /plugins
├─ 外部核验                   /verification
└─ 数据源与集成               /integrations

系统管理
├─ 用户与权限                 /settings/users
└─ 系统设置                   /settings
```

附加页面：

- `/audit-cases/:id`：审计案件工作区
- `/rules/:id`：规则编辑器

导航可见性由功能开关/路由注册表驱动：页面未完成时隐藏入口，不渲染不可点击的“即将上线”菜单。比赛演示版首批显示“审计驾驶舱、审计队列、复核中心、规则管理、案例验证”；其余页面完成后再出现。

### 3.2 侧栏行为

- 侧栏适用于 12 个分组目的地，层级不超过 2 层。
- 当前模块展开，其他分组允许折叠；用户选择保存在本地。
- 徽标只显示需要行动的数量，例如“待复核 3”，不显示装饰性计数。
- 帮助、用户和退出属于工具导航，放在底部或顶栏用户菜单，不与业务导航混排。
- 侧栏在所有路由（含审计案件工作区与运行轨迹）都保持用户选择的展开/收起状态，切换模块不受影响；仅当视口宽度 ≤1023px 时收窄为 64px 图标栏。

### 3.3 响应式

| 宽度 | 全局导航 | 审查工作区 |
|---|---|---|
| `≥1280px` | 232px 侧栏，可收起 | 三栏 `Splitter` |
| `1024–1279px` | 保持用户选择的展开/收起状态 | 左侧发现栏可折叠；原文 + 右栏 |
| `768–1023px` | 64px 图标栏 | 原文主区；发现列表和复核面板用抽屉 |
| `<768px` | 顶部按钮 + `Drawer` | `Tabs`：合同原文 / 风险发现 / 依据与复核 |

移动端用于查看和轻量复核，不承诺完整规则编辑体验。

### 3.4 顶栏

常态只显示面包屑、页面级操作和用户菜单。服务健康状态仅在降级、断开或重连时出现；“实时更新”属于当前审计案件状态，放在案件头部。

## 4. 核心页面

### 4.1 审计驾驶舱 `/dashboard`

目标：在一个屏幕内回答四个问题：处理了多少、要处理什么、耗时如何、确认了哪些风险。

#### 第一行：运营 KPI

1. 本期审计案件数
2. 审查中位耗时
3. 待复核案件数
4. 未闭环高风险数

不使用“平均耗时”作为唯一耗时指标，避免少数长尾案件扭曲结果；点击卡片进入已带筛选的队列。

#### 第二行：趋势与风险结构

- 左：近 30 天“审计完成数 / 待复核新增数”的折线图。
- 右：按数量降序的风险类型横向条形图。条长负责比较，颜色只区分风险等级。
- 不使用环形图、饼图和仪表盘。

#### 第三行：质量与行动

- 质量指标：证据完整率、风险确认率、自动审查完成率。每项显示口径说明。
- 待办列表：最多 5 条，显示合同名称、当前状态、更新时间和主操作。
- 若样本数不足，不显示百分比趋势，显示“样本不足”。

### 4.2 审计队列 `/audit-cases`

#### 头部

```text
审计队列
按最近更新排序，优先处理待复核、异常和未闭环高风险案件。
                                     [刷新] [新建审计]
```

#### 汇总条

四张紧凑卡：待复核、处理中、异常、今日完成。浅色底、左侧语义色条和明确文本三重编码；整卡可点击筛选。

#### 工具栏

- 搜索：`搜索合同名称 / 审计 ID / 来源记录 ID`
- 状态筛选
- 风险等级筛选
- 更多筛选
- 列设置

主要按钮不超过 5 个；低频操作进入 `Dropdown`。

#### 表格列

| 列 | 主内容 | 副内容 |
|---|---|---|
| 合同 | `contractTitle` | 合同版本、来源类型 |
| 审计 ID | 短 ID + 24px 复制按钮 | 完整 ID 放 tooltip/详情 |
| 风险 | 最高风险等级 + 数量 | 无发现显示 `-` |
| 状态 | 审计案件状态 | 当前审计阶段 |
| 更新时间 | 相对时间 | tooltip 显示绝对时间 |
| 操作 | 打开 / 取消 / 重试 | 依状态显示 |

合同名称属于 `Contract`，审计 ID 属于 `Audit Case`。没有合同名称时显示“未命名合同”，并提供设置名称的入口；不得把 ID 伪装成合同编号，也不得持久化“合同审计 + ID”作为名称。

行点击可以打开详情，但键盘用户仍有明确的“打开”按钮。状态、时间和操作文本不换行；空值统一显示 `-`。

### 4.3 审计案件工作区 `/audit-cases/:id`

这是 v1.2 的核心改造。

#### 案件头部

```text
[返回审计队列]  审计队列 / 设备采购合同 / 审计案件
设备采购合同 · V3                 [高风险] [待人工复核] [实时更新]
审计 ID a3f1c2e8… [复制]  来源：MinIO  创建：2026-09-11 20:15
```

- “返回审计队列”使用左箭头 + 文本，命中区至少 32px 高。
- 若从驾驶舱或复核中心进入，返回链接跟随 `origin` 查询参数；无来源时回到审计队列。
- 页面刷新后也能通过 URL 恢复筛选和所选发现。

#### 三栏工作区

```text
┌─ 风险发现 280 ─┬──────────── 合同原文 flex ────────────┬─ 依据与复核 392 ─┐
│ 全部 5           │ 第 4 章 付款与结算                    │ 预付款比例超过制度上限 │
│ 待复核 2         │                                      │ 高风险 · 待复核       │
│                  │ 4.2 甲方应在合同签订后五日内支付      │                    │
│ [高] 预付款超限   │ [预付款 70%]，余款在验收后支付。       │ 实际值 70%             │
│ [中] 主体信息冲突 │  红色底纹 + 左侧风险标记               │ 制度上限 30%           │
│ [中] 资质待核验   │                                      │ 差额 40pp              │
│                  │ 第 5 章 交付……                        │                    │
│ 审查覆盖          │                                      │ 违反规则 2 条          │
│ 通过 18 / 不适用 4 │                                      │ 证据来源 3 条          │
│                  │                                      │ 修复建议……             │
│                  │                                      │ [判定误报] [确认风险]  │
└──────────────────┴──────────────────────────────────────┴────────────────────┘
```

##### 左栏：风险导航

- 默认只列“违反规则”和“需要人工复核”的发现，按风险等级、证据不足、原文顺序排序。
- 每项显示等级、短标题、所在章节和复核状态。
- “审查覆盖”单独入口显示所有规则：通过、违反、不适用、证据不足。通过规则不占用主风险列表。
- 一个风险发现可以关联多个规则评估和多条证据。

##### 中栏：合同原文

- 显示完整 `Contract Document`，保留章节、段落、表格和稳定区块 ID。
- 选中发现后滚动到 `blockId + startOffset + endOffset`，并保持上下文，不只显示被截断引文。
- 风险原文：浅红底、红色左标记、波浪下划线；待核验证据：浅橙底；当前选中增加蓝色外框。
- 点击高亮反向选中左栏发现；不同发现重叠时显示编号并允许切换。
- 原文、证据和法规依据不使用相同颜色：原文问题为红/橙，制度依据为品牌蓝。

##### 右栏：依据与复核

顺序固定，降低复核成本：

1. 发现标题、风险等级、机器建议状态
2. 事实比较：实际值 / 制度上限 / 差额
3. 违反规则列表：规则名、版本、处置、适用条件
4. 证据来源列表：合同定位、制度条款、外部核验结果
5. 修复建议：删除、修改或插入条款的建议文本
6. 人工复核操作

操作文案不用“接受建议 / 驳回建议”，改为业务结论：

- 主操作：**确认风险** → 映射 `ACCEPTED`
- 次操作：**判定误报** → 映射 `REJECTED`，必须填写理由
- 证据冲突时：**转人工补充核验**，不允许系统自动替人作结论

#### 多规则与多证据

当前前端数据结构只有 `snapshot.ruleAssessment` 单对象，无法支持标注 #9。目标结构：

```ts
interface AuditCaseDetailDataV2 {
  case: AuditCase;
  contract: {
    id: string;
    title: string;
    revision: string;
  };
  snapshot: {
    document: ContractDocument;
    facts: PaymentFacts;
    evidence: EvidenceLocator[];
    ruleAssessments: Array<RuleAssessment & {
      id: string;
      ruleVersion: string;
    }>;
  };
  findings: FindingRevision[];
}
```

`FindingRevision` 需要能引用多个 `ruleAssessmentId` 和 `evidenceId`。所有引用必须验证属于同一不可变 `AuditSnapshot`。

### 4.4 复核中心 `/reviews`

面向人工处理，不复制审计队列：

- 左侧队列：按 SLA、风险等级、证据冲突排序。
- 主区复用三栏审查工作区。
- 筛选：待我处理、临近超时、证据不足、已转交。
- 批量操作只允许转交和设置优先级；不得批量确认风险或批量判定误报。

### 4.5 整改跟踪 `/remediations`

看板只用于阶段流转，不用于展示大段合同内容：待整改、整改中、待复核、已关闭。卡片显示合同名称、风险摘要、责任人和截止时间；打开后仍回到审查工作区的整改视图。

## 5. 治理与扩展页面

### 5.1 规则管理 `/rules`

表格字段：规则名、规则代码、适用合同类型、当前版本、状态、最近验证、发布人。

“状态”必须区分两个互不相干的维度，不能合并成一列：

- **版本状态**（`已发布` / `草稿` / `已退役`）是版本的生命周期。发布新版本时，上一已发布版会被置为“已退役”（`已退役` = superseded by a newer published version），历史发现仍引用其版本号。
- **运行开关**（`运行中` / `已停用`）是规则是否进入新的审计。停用需要填写原因并记录操作人；被停用的规则不进入新审计快照（重试同样跳过），重新启用即恢复。版本状态与运行开关不同步：一个已退役版本不会因新版本发布而重新生效，一个已发布版本也可以被单独停用。

规则编辑器 `/rules/:id` 采用“基础信息 / 审查逻辑 / 条款立场 / 验证案例 / 发布记录”五区：

- 审查逻辑保存确定性规则输入和输出。
- 条款立场区允许配置“首选、可接受退让、不可接受、例外审批条件”。
- “规则”和“问题”分开：规则产生可执行评估；问题只补充需要模型回答的上下文。
- 发布前必须运行案例验证，失败时阻止发布。

### 5.2 案例验证 `/cases`

展示正例、反例、边界例、历史误报和证据缺失案例。支持按规则版本运行验证；结果显示通过率、回归差异和具体失败，不用单一分数掩盖错误。

### 5.3 法规知识库 `/regulations`

三栏：法规树、正文、引用该条款的规则。条款保留版本、生效时间、地域、适用范围和来源 URL；过期版本仍可追溯，不覆盖历史审计依据。

### 5.4 能力插件 `/plugins`

卡片显示能力类别、版本、健康状态、最近调用、权限范围；启停属于高风险操作，需要确认和审计记录。解析、规则、外部查询、语义审查分组展示。

### 5.5 外部核验 `/verification`

展示企查查等来源的查询记录、命中主体、来源时间、缓存时效和证据引用。核验结果是 `Source Record`，不是直接审计结论。

### 5.6 数据源与集成 `/integrations`

展示 MinIO、PostgreSQL、MCP 服务和模型服务连接。凭据只显示已配置状态，永不回显明文；连接测试结果包含时间、延迟和可读错误。

### 5.7 用户与权限 `/settings/users`

角色至少区分审计员、复核人、规则管理员、系统管理员。权限按操作和数据范围配置；确认风险、发布规则、导出合同原文都记录审计日志。

### 5.8 系统设置 `/settings`

分区：审计策略、模型与超时、通知、数据保留、安全与审计日志。危险设置单独分区并要求二次确认。

## 6. 关键状态与边界

每个核心页面必须设计以下状态，不在实现时临时补：

| 状态 | 设计 |
|---|---|
| 首次使用 | 说明能力边界 + 明确主操作 |
| 无搜索结果 | 保留筛选条件，提供清除筛选 |
| 加载 | 骨架屏保持页面结构，避免整体旋转图标 |
| 部分失败 | 保留已加载内容，在对应面板重试 |
| 实时断开 | 案件头部显示“实时连接已断开”，允许手动重连 |
| 权限不足 | 解释缺少的权限和可联系角色，不显示空白页 |
| 长合同 | 虚拟化原文区块；目录和稳定锚点持续可用 |
| 多发现重叠 | 编号标记 + 弹层选择，不互相覆盖 |
| 无风险发现 | 显示已完成的规则覆盖和证据完整度，不用庆祝性文案 |
| 证据冲突 | 强制进入人工补充核验，不自动确认或驳回 |

## 7. 可访问性与交互约束

- 所有文字和关键图标满足 WCAG 2.2 AA 对比度。
- 点击目标至少 24×24 CSS px，主要按钮和表格操作达到 32px 高。
- 图表必须有表格替代视图；高风险不只用红色表达。
- 所有菜单、Splitter 折叠、发现选择、原文跳转和复核对话框支持键盘。
- 图标按钮有 `aria-label` 和 tooltip；装饰图标 `aria-hidden`。
- 表格时间列、状态列和操作列保持单行；长合同名允许两行后省略并提供 tooltip。
- 动效只用于面板展开、原文定位和状态变化；遵循 `prefers-reduced-motion`。
- 不使用 emoji 作为导航、状态或操作图标。

## 10. 研究依据

- Ant Design，Navigation：侧栏适合 6 个以上目的地；信息架构应浅、平、宽；沉浸式复杂任务可减少全局导航干扰。  
  https://ant.design/docs/spec/research-navigation/
- Ant Design，Detail Page：详情页需要直接、扁平、层级清楚，并按相关性拆分复杂信息。  
  https://ant.design/docs/spec/detail-page/
- Ant Design，Data Display：字段按重要性和关联性组织；表格必须处理空值、筛选和分页。  
  https://ant.design/docs/spec/data-display/
- Carbon Design System，Data Table：搜索、筛选和主要操作进入表格工具栏；空间不足时使用独立页面或侧面板，不把所有信息塞进展开行。  
  https://carbondesignsystem.com/components/data-table/usage/
- Nielsen Norman Group，Dashboards：仪表盘应支持一屏快速判断；条长和二维位置比角度、面积更容易比较，因此优先折线图和条形图。  
  https://www.nngroup.com/articles/dashboards-preattentive/
- W3C WCAG 2.2，Use of Color：颜色不能是传达信息、动作或状态的唯一手段。  
  https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html
- W3C WCAG 2.2，Target Size Minimum：AA 最小目标为 24×24 CSS px或满足间距例外。  
  https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html
- Ironclad AI Playbooks：合同审查需要原文预览、规则快速跳转、首选/退让/不可接受立场及条款插入、修改、删除建议。  
  https://support.ironcladapp.com/hc/en-us/articles/12275685560215-Ironclad-AI-Playbooks-Overview
- Spellbook Playbooks：规则和问题应分开；引用应能跳到支持文本，审查建议需要可应用或编辑。  
  https://help.spellbook.legal/en/articles/9926250-playbooks-overview
- Ant Design Charts，Quick Start：React 官方图表包 `@ant-design/charts`。  
  https://ant-design-charts.antgroup.com/en/manual/getting-started
